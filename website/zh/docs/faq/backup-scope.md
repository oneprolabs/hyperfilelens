# 备份范围与系统路径

HyperFileLens 对主机备份源执行的是文件级保护。可以把 `/` 或盘符根路径选进备份范围，但 Agent 会按内置边界规则自动排除部分操作系统运行时路径。其余内容是否进入快照，还取决于读权限、文件类型以及备份策略与文件过滤器。

本页说明当前版本的预期行为。选择目录的一般原则见[管理备份源](/zh/docs/backup-restore/sources)；策略与过滤器设置见[策略与保留](/zh/docs/backup-restore/policies)。

## 文件级备份与根目录

在 Linux、Windows 或 macOS 主机上，可以把根路径选为备份源目录。这与[限制与安全建议](/zh/docs/reference/limitations-security)中的边界一致：

- 文件级备份不自动提供数据库、虚拟机或业务应用的一致性副本；
- 也不等同于可直接用于裸机还原的系统盘镜像。

备份上级路径时，若范围覆盖到 Agent 根目录，该目录会被排除，避免把产品运行目录写入快照。日常保护业务数据时，仍应优先选择明确的数据目录，而不是整棵根目录。

## 自动排除的系统路径

当备份源覆盖到下列路径时，Agent 按内置边界规则加入忽略项，并在结果中记录已排除的系统路径。排除是预期行为，不代表任务失败。

| 平台 | 自动排除 |
| --- | --- |
| Linux | `/proc`、`/sys`、`/dev`、`/run` |
| macOS | `/.vol`、`/dev`、`/private/var/run`、`/private/var/vm`、`/System/Volumes/VM` |
| Windows | `System Volume Information`、`pagefile.sys`、`hiberfil.sys`、`swapfile.sys`、`DumpStack.log.tmp` |

不能把上表中的受保护路径本身直接选为备份源。例如单独选择 `/proc` 会被拒绝。

若 Agent 额外配置了系统边界路径，也会在覆盖到时一并排除。

## `/lib` 与普通系统目录

`/lib`、`/lib/modules` 等目录不在上表自动排除名单中，按普通目录处理。Agent 有权限读取的普通文件可以进入快照。

因此，即使备份范围包含根目录或 `/lib`，也不能假定快照中一定有完整的 `/lib/modules`。以快照内容和任务详情为准。

## 策略与过滤器的影响

快照中缺少预期内容时，通常与下列配置或运行条件有关，而不是产品固定禁用 `/lib` 等普通系统目录：

| 配置位置 | 影响 |
| --- | --- |
| 文件过滤器中的 **仅当前文件系统** | 只扫描源路径所在文件系统；落在其他挂载点上的内容不会进入快照 |
| 文件过滤器中的排除规则、最大文件大小、缓存目录选项 | 匹配规则的内容不会进入后续快照 |
| 备份策略中不可读目录、不可读文件的处理 | 开启跳过后，无权读取的项可能被跳过 |
| 备份策略中不支持文件系统项的处理 | 开启跳过后，socket、设备节点等特殊项可能被跳过；未开启时，同类项可能在任务中报错 |

规则与策略变更只影响后续快照，不会补充已有快照中从未备份的文件。

## 核对建议

备份任务成功或部分成功，只说明本次任务按策略与边界规则结束。被自动排除、被过滤器排除或被策略跳过的内容不会出现在快照中。

如果依赖根目录或系统路径中的关键文件，建议：

1. 打开快照浏览器，确认关心的路径和文件是否存在；
2. 查看任务详情中的跳过项、错误或诊断信息；
3. 将代表性文件恢复到独立目录，核对内容是否可读。

不要把任务成功作为唯一依据，确认关心的路径已经进入快照。
