# 托管存储概述

::: info 适用范围
本指南面向 Personal Edition 运营方，需要企业版支持，并由个人版组织中具有 Managed Storage 管理权限的人员操作。个人版普通用户无需配置云存储身份或密钥。
:::

<p class="hfl-doc-lead">运营方准备存储和签发身份，HyperFileLens 为个人用户创建独立仓库。用户通过备份向导使用仓库，不需要持有运营方的长期云密钥。</p>

## 与普通目标存储的区别

| 方式 | 配置入口与职责 | Bucket 与仓库 |
| --- | --- | --- |
| 普通对象存储仓库 | 普通组织按[管理目标存储](/zh/docs/backup-restore/targets)添加仓库 | 按普通仓库向导配置，不套用本指南的托管签发身份 |
| 个人版托管存储 | 运营人员在 Personal Edition 的 Managed Storage 配置连接 | Bucket 必须提前存在；一个连接可承载多个独立仓库，每个仓库有独立 UUID 前缀和 Kopia 密码 |

Managed Storage 仅适用于支持该能力的组织。需要企业版、当前组织支持该能力，以及有效的组织管理授权。11444 Admin Console 的平台身份本身不替代 11443 当前组织内的授权。角色与资源范围见[角色与权限](/zh/docs/governance/roles)。

## 接入流程

```text
存储管理员：创建专用私有 Bucket、配置签发身份和最小权限
      ↓ 确认连接参数，通过安全渠道配置签发密钥
Personal Edition 运营人员：保持个人注册关闭 → 添加连接
      ↓ 只读校验 → 保存（默认启用；没有默认连接时自动设为默认）
运营人员：用已有测试成员完成验证 → 确认生产默认连接
      ↓ 验证通过后开放个人注册
      ↓
系统：新用户注册时建仓 / 管理员为已有成员创建或补建
      ↓
独立仓库：personal/repositories/<repository_uuid>/
      ↓
个人用户：通过 Backup Wizard 备份和恢复自己的数据
```

源端 Agent 上的 Kopia 客户端直接访问对象存储，不通过控制端中转备份数据。Private Data Gateway 等执行组件按具体任务取得需要的访问身份；网络规划见[网络与端口](/zh/docs/deployment/network)。

## 选择接入指南

| 存储 | 签发方式 | 管理员需要准备 |
| --- | --- | --- |
| [华为云 OBS](./huawei) | IAM v3 普通账号委托签发临时 AK/SK/Token | 专用 IAM 用户、指定委托授权、委托及 OBS 资源策略、资源账号 Domain ID |
| [阿里云 OSS](./aliyun) | 阿里云 STS AssumeRole | 专用 RAM 用户、指定角色调用授权、角色信任策略与 OSS 资源策略 |
| [AWS S3](./aws) | AWS STS AssumeRole | 专用 IAM 用户、指定角色调用授权、角色信任策略与 S3 资源策略 |
| [RustFS](./rustfs) | RustFS 自身的 SigV4 AssumeRole | 支持该接口的部署、普通 IAM 用户及前缀策略，不是 Service Account |
| [MinIO](./minio) | MinIO 自身的 SigV4 AssumeRole | 支持该接口的部署、普通内置用户及前缀策略，不是派生 Access Key |

**S3 API 兼容不等于 STS 签发接口相同。** 各服务商须使用对应的身份签发配置。仅支持 S3 读写的服务，不一定满足托管连接所需的 STS 能力。

## 统一的命名与权限范围

```text
hfl-backups-prod                     # 示例 Bucket，必须提前存在
└── personal/                        # Add Object Storage 的 Object Prefix
    └── repositories/                # 系统追加
        ├── <repository_uuid_a>/     # 用户 A 的仓库
        └── <repository_uuid_b>/     # 用户 B 的仓库
```

- Bucket 名称和 `personal/` 是建议值，可以在新建连接时修改；前缀应为以 `/` 结尾的规范路径，不含通配符。云策略必须同步修改。
- 云端连接身份只需覆盖 `personal/repositories/*` 的业务范围，而不是整个 Bucket 的对象内容。
- 下发给执行组件的会话按实际仓库 UUID 进一步收窄。普通用户间的资源隔离还依赖组织、Owner、显式共享和角色授权，不仅依赖路径。
- 查询桶信息和清理 Multipart 的元数据权限可能是指定 Bucket 级别。各指南会单独列出，不把它们混同于读取其他前缀的对象内容。
- 本指南按普通私有 Bucket 编写。WORM/Object Lock、归档、KMS 加密、跨账号 Bucket Policy、网络来源限制需另行核对，不在示例中自动授予全权权限。

## 凭据与网络边界

- 长期签发 AK/SK 仅保存在控制端，不交给个人用户、Agent 或 Proxy；不要把密钥写进截图、工单、代码仓库或命令历史。
- 系统调用签发接口创建临时 AK/SK/Token，当前默认请求 `900` 秒。服务商允许的最大会话时长不是默认签发时长。执行授权与云 Token 的生命周期不同，长任务由受控续签衔接，无需将单次 Token 的有效期延长至数天。
- 执行组件需要实际可达的存储 Endpoint；控制端还需要可达 IAM/STS。控制端不运行在相应云上时，不要提供只能在云内访问的 Endpoint。自建服务使用能被所有执行组件访问的地址，而不是只在控制端有效的 `localhost`。
- HTTPS 证书链必须被相关组件信任；不要用关闭校验或公开 Bucket 解决 TLS、权限或网络问题。RustFS/MinIO 的内网 HTTP 例外见各自指南。

## 默认连接与历史成员

打开 **Managed Storage → Object Storage**，由有管理权限的运营人员添加连接。新连接默认启用，无需单独激活；页面不提供 Disable 操作。没有默认连接时，新连接保存后会自动设为默认；已有默认连接时，新增连接不会替换它。新连接验证通过后，如需承接后续个人注册，再使用 **More Actions → Set as Default** 切换。

如需恢复已有的 Disabled 连接，选择该连接后使用 **More Actions → Enable**，需要连接管理权限。系统在启用前重新检查临时凭据签发和只读访问；检查失败时，连接保持停用状态，不变更现有默认连接。启用成功后，已有默认连接保持不变；没有默认连接时，恢复的连接会自动成为默认。恢复操作同样应遵循本页的验证流程，在验证完成并确认生产默认连接后再开放个人注册。

::: warning 首次配置期间保持个人注册关闭
第一个连接保存后就可能立即用于新用户注册，并不会等待写入、初始化和恢复测试完成。首次配置期间应保持个人注册关闭，使用已有测试成员验证，或在受控测试环境中完成验证。确认生产默认连接并完成验收后，再开放个人注册。连接显示 Enabled 不表示这些测试已经通过。
:::

个人注册依赖已启用的默认连接；没有该连接时，应先完成存储配置，不要通过修改普通用户角色放开存储管理页面。

新个人用户注册时使用当时的默认连接创建独立仓库。历史成员不会仅因新增连接自动全部补建。使用 **Backup Repositories → More Actions → Provision Missing Repositories** 查看实际预览，只处理系统判定为缺少仓库的合格成员；Owner、停用成员等可能不在候选范围。候选人数以实际预览结果为准，不一定等于组织成员总数。

补建仅适用于符合条件的缺失仓库，不用于初始化失败重试或恢复已删除仓库。已有初始化失败仓库使用 **Retry Initialization**；删除中或保留的记录按其状态排查。更换默认连接不会迁移已有仓库或回收云上的旧数据。

### 仓库数量与历史记录

Object Storage 中的 Repositories 仅统计当前未删除的关联仓库，不包括已删除的历史记录。创建中、创建失败、删除中以及删除失败的仓库，在尚未标记删除时仍计入数量。

数量为 0 不代表连接一定可以删除。历史仓库关联可能仍用于清理、审计和保留数据管理；存在这类关联时，系统继续保护连接及其签发配置，不因数量归零而删除历史记录或放开连接删除。

## 验证与上线

| 阶段 | 检查内容 | 不能据此推断 |
| --- | --- | --- |
| 保存连接 | 签发临时身份并执行仓库前缀内只读列举；校验失败不保存连接或切换默认 | 尚未验证对象写入、维护与删除权限 |
| 初始化仓库 | 独立位置、密码和真实仓库初始化成功 | 尚未覆盖每个源端的连通性或长任务续签 |
| 备份恢复 | 测试成员备份并恢复文件，内容一致，其他普通成员不可见 | 不能据此声称所有版本或所有云环境均已兼容 |
| 生命周期 | 按需在可丢弃仓库验证维护、续签、取消与物理清理 | 删除不可回滚，不对生产仓库做破坏性试验 |

首次配置及验证期间保持个人注册关闭，或在受控测试环境验证。没有默认连接时，第一个连接保存后就会自动成为默认，不要假定还需单独启用才能参与注册。完成上表测试并确认生产默认连接后，再开放个人注册。记录服务商、服务端版本、地域、Endpoint 类型、策略版本与测试结果。本文档介绍受支持的配置方式；生产上线前，仍须在目标环境完成上述验证。

## 配置准备与凭据管理

存储管理员负责创建 Bucket、配置签发身份和最小权限策略；具有 Managed Storage 管理权限的运营人员负责添加连接、验证仓库并配置默认连接。各服务商指南末尾的「配置核对清单」列出了授权要求和所需配置信息。

首次部署建议新建专用的私有空 Bucket，并在添加连接前完成创建；无需预先上传对象或手动创建仓库目录。签发密钥通过安全渠道配置到控制端，不写入普通工单、文档或代码仓库，也不得下发给普通用户或执行组件。临时凭据由系统按需签发，无需手动准备临时 Token 或提供云平台主账号密码。
