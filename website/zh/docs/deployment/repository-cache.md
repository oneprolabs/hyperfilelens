# 仓库缓存管理

<p class="hfl-doc-lead">Agent 与 Proxy 使用本地仓库缓存，避免反复下载或重建相同的仓库数据。当前支持缓存管理的节点会按需增长缓存，并在新备份前执行磁盘空间预检查。</p>

## 缓存的内容和作用

仓库引擎会在本地保存两类可重建的数据：

- **元数据缓存**：访问、校验和枚举备份数据所需的仓库与快照元数据。反复列出快照或访问大量小文件时，这类缓存尤其有帮助。
- **内容缓存**：备份、恢复、下载、浏览以及其他内容操作中从仓库读取的内容。复用已预热的内容可以减少重复远端读取。

当前布局会把活动缓存放在 Agent 安装根目录下的 `cache/repositories/`。仓库连接配置和身份信息是独立数据，仍保存在 Agent 的受保护数据目录中，不属于可删除的缓存。缓存属于每个 Agent 或 Proxy 本地使用；多台主机访问同一仓库时不会共享本地缓存。

缓存是性能辅助数据，不是备份本身。删除已完成且受管的缓存后，后续操作会从仓库重新建立缓存，不会删除快照，也不需要重新注册。不要为了释放缓存空间而删除 Agent 根目录、连接配置、凭据、任务数据库、日志或恢复输出。

## 当前缓存管理模式

声明 `cache_management_v1` 能力的 Agent 或 Proxy 使用 HyperFileLens 管理的**按需缓存**模式：

- 内容缓存和元数据缓存按操作需要增长；
- 没有固定的内容／元数据容量分配，也没有配置得到的缓存容量硬上限；
- 普通恢复、下载、浏览和内容读取仍然会使用缓存；
- 已有的热缓存会继续复用，Agent 升级不会自动清空；
- 旧版缓存实现的零值语义仍然有效：`0` 会关闭对应的旧式缓存设置，**不表示不限容量**。

按需增长不会预留磁盘空间，也不会让文件系统变成无限容量。真正的保护边界是下面说明的 Agent 备份前置检查。前置检查通过后，日志、临时文件、恢复输出或正在运行的操作仍可能继续消耗空间。

### 旧节点兼容行为

不具备 `cache_management_v1` 能力的节点继续使用旧的“每个仓库固定预算”行为。此时控制台中的旧缓存设置含义如下：

| 项目 | 旧节点行为 |
| --- | --- |
| 作用范围 | 所选 Agent 或 Proxy 上的每个受管仓库连接 |
| 默认预算 | `8192 MB` |
| 可配置范围 | `0～65536 MB` |
| 分配方式 | 内容缓存约 75%，元数据缓存约 25% |
| `0` | 关闭旧的内容缓存和元数据缓存设置，但不会立即删除已有文件 |

这张表不适用于已经具备 `cache_management_v1` 的节点。控制台会保留旧节点的设置方式；如果节点需要升级才能使用新的缓存管理控制，会显示升级提示。

## 配置和查看受管缓存

1. 打开<span class="hfl-path">数据保护 → 生产站点</span>。
2. 选择<span class="hfl-ui">源端主机</span>或<span class="hfl-ui">代理主机</span>，然后打开主机详情。
3. 进入<span class="hfl-ui">高级设置 → 缓存管理</span>。
4. 查看当前缓存目录、缓存占用、缓存所在文件系统的可用空间和上次采样时间。
5. 需要新的 Agent 侧测量时，使用<span class="hfl-ui">刷新</span>。页面显示的是最近一次采样，不是持续监控结果。

节点在线且具备能力时，缓存管理面板提供以下操作：

- **阻止阈值**：可用空间低于此值时，阻止下一次备份前置检查。
- **警告阈值**：自动计算为阻止阈值加 `10 GiB`。
- **更换缓存目录**：把受管缓存根目录迁移到其他文件系统或目录父级。
- **刷新**：请求当前缓存占用和可用空间采样。

修改阈值会创建独立的缓存策略任务，需要节点在线且可路由。这不是缓存大小设置。下一次与备份相关的操作会在准备仓库前重新检查已保存的策略；不会强制重启正在运行的任务。

## 磁盘空间保护

默认策略使用二进制 GiB（`1 GiB = 1,073,741,824 bytes`）：

```text
阻止阈值：可用空间 10 GiB
警告阈值：可用空间 20 GiB
警告阈值 = 阻止阈值 + 10 GiB
```

检查的是活动缓存根目录所在文件系统的可用空间，使用运行 Agent 的账号执行。对于备份相关操作：

| 可用空间 | 结果 |
| --- | --- |
| `>= 警告阈值` | 正常继续 |
| `>= 阻止阈值` 且 `< 警告阈值` | 记录低空间警告并继续 |
| `< 阻止阈值` | 在备份／仓库准备前停止 |
| 无法查询空间 | 单独报告空间检查失败，不伪造为零空间 |

这是**备份前置检查**，不是空间预留、持续监控，也不是缓存目录的硬配额。检查通过后空间仍可能被消耗。如果操作被阻止，请释放空间、扩容或安全地更换缓存目录，然后重新运行备份。降低阈值不会创造磁盘空间。

规划时应在预期缓存增长之外，额外考虑日志、索引、临时文件、恢复输出和同一文件系统上的其他负载。把默认的 `20 GiB` 看作警告余量，而不是适用于所有负载的充足空间保证；不要把当前全部可用空间都分配给缓存增长。

## 更换缓存目录

要迁移受管缓存，请在<span class="hfl-ui">更换缓存目录</span>中选择一个已经存在且可写的目录父级。HyperFileLens 会创建类似 `.hyperfilelens-cache-<installation-id>` 的安装专属子目录，不会接管任意已有的非空目录。

迁移过程中，Agent 会等待正在使用缓存的操作退出，重新校验目标目录，确认安全后才切换活动根目录。旧缓存内容**不会复制**到新位置，因此新缓存需要重新预热，可能再次从仓库下载数据。只有新根目录生效后，系统才会清理旧的受管缓存。

目标不能是系统路径、真实仓库、恢复输出目录、受保护的 Agent 状态路径，也不能与旧缓存重叠。如果准备或校验失败，旧目录继续使用。如果新目录已经生效但旧目录清理失败，页面会显示**清理待完成**：继续使用新目录，解决文件系统或权限问题后重试清理，不要手动切回旧目录。

备份、恢复、仓库服务或维护进程正在使用缓存时，不要迁移目录。迁移只改变缓存位置，不会移动快照、凭据、连接配置、任务历史或业务数据。

## 按工作负载规划

| 工作负载 | 建议 |
| --- | --- |
| 大量小文件 | 为元数据增长预留空间，并预期随机元数据 I/O。实测重复列目录和恢复任务；按需模式不应再把固定 75/25 比例当作调优目标。 |
| 大文件 | 为重复内容读取以及恢复／下载突发流量预留空间。单独检查恢复输出的临时空间，因为它不属于缓存配额或缓存占用。 |
| 混合负载 | 使用有代表性的备份、浏览、恢复和下载任务，比较耗时、远端读取、缓存占用和剩余空间，不要假定一个通用的缓存与数据比例。 |
| 公网对象存储 | 关注延迟、重复下载、请求次数以及供应商的出口或传输费用。本地热缓存可以减少重复读取，但不能消除新数据产生的仓库请求和网络成本。 |

## 故障排查

- **`CACHE_SPACE_INSUFFICIENT`**：释放空间、扩容或完成安全的缓存迁移，然后启动新的备份；仅修改阈值不会自动重试被阻止的操作。
- **`CACHE_SPACE_CHECK_FAILED`**：检查活动缓存挂载是否存在，以及 Agent 运行账号能否检查该文件系统。测量失败不等于可用空间为零。
- **目标目录校验失败**：选择绝对路径、已存在且可写的父目录，并避开受保护路径、仓库路径、恢复输出、嵌套路径和未受管的非空目录。
- **迁移后清理待完成**：不要删除 Agent 根目录，也不要手动切换引用。解决旧目录的权限、挂载或锁问题后重试清理。
- **时间戳较旧**：缓存状态按需采样或在受管操作中更新，不是实时文件系统监控。

节点注册或连接问题请查看[安装与节点](/zh/docs/troubleshooting/installation-nodes)。备份或恢复失败请查看[备份、存储与恢复](/zh/docs/troubleshooting/protection)。
