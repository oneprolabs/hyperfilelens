# 仓库缓存配置

<p class="hfl-doc-lead">Agent 与 Proxy 使用本地 Kopia 缓存，减少重复读取仓库数据的开销。根据执行主机的可用磁盘空间和仓库连接数量调整缓存预算，无需重新安装组件。</p>

## 适用范围

这项设置作用于所选 Agent 或 Proxy 上的每个受管仓库连接，不是整台主机所有仓库共用的总额度。同一仓库由多台主机访问时，各主机分别使用自己的本地缓存；同一主机上的不同仓库连接也可能分别占用空间。

仓库缓存使用本地磁盘，不是内存额度、目标存储容量，也不是安装包下载缓存。Private Data Gateway 不提供这项配置入口；其智能洞察运行资源不在本页的配置范围内。

## 在控制台配置

1. 打开<span class="hfl-path">数据保护 → 生产站点</span>，选择<span class="hfl-ui">源端主机</span>或<span class="hfl-ui">代理主机</span>。
2. 打开需要调整的主机详情，进入<span class="hfl-ui">高级设置</span>。
3. 在<span class="hfl-ui">仓库缓存</span>中修改<span class="hfl-ui">每个仓库的 Kopia 缓存</span>。
4. 核对该页的其他资源设置，然后选择详情页底部的<span class="hfl-ui">保存更改</span>。保存会一并提交该页的资源设置。

| 项目 | 说明 |
| --- | --- |
| 单位 | MB，填写整数 |
| 默认预算 | 控制台与正常受管仓库任务下发的默认值为 `8192 MB`；已有连接的实际配置需等待后续仓库操作应用 |
| 可配置范围 | `0～65536 MB` |
| 作用范围 | 所选主机上的每个受管仓库连接 |
| 设为 `0` | 关闭内容缓存和元数据缓存，不表示关闭所有类型的缓存或立即删除已有缓存文件 |

已有自定义设置时，以页面中的已保存值为准。此处的默认值面向控制台管理的仓库任务，不代表独立运行 Kopia 命令时的默认行为。

## 缓存如何分配

非零预算由 Agent 在内容缓存和元数据缓存之间自动分配，通常约为 **75%／25%**：

- **内容缓存**：缓存从仓库读取的数据内容。
- **元数据缓存**：缓存用于访问仓库和快照的元数据。

内容缓存按总预算的四分之三向下取整，至少分配 `1 MB`；元数据缓存使用剩余预算。用户配置的是两者的合计预算，不能在控制台单独调整这两个比例。

| 配置值 | 内容缓存预算 | 元数据缓存预算 |
| --- | --- | --- |
| `0 MB` | 关闭 | 关闭 |
| `4096 MB` | `3072 MB` | `1024 MB` |
| `8192 MB` | `6144 MB` | `2048 MB` |
| `16384 MB` | `12288 MB` | `4096 MB` |

**75%／25% 是缓存预算的内部分配比例，不是缓存占备份数据量、主机内存或磁盘总容量的比例。** 系统不会根据这些容量自动计算本项设置，也没有适用于所有数据集的固定缓存占比。

## 生效与验证

保存成功表示设置已经提交，不代表所有仓库连接已立即更新。新的缓存预算在下一次安全的受管仓库操作中应用；正在运行的任务或长期运行的仓库服务不会因此被强制重启。

1. 确认 Agent 或 Proxy 在线。
2. 等待该主机执行后续备份、恢复等涉及仓库访问的任务。
3. 查看高级设置中的 Agent 应用状态，区分<span class="hfl-ui">等待应用</span>、<span class="hfl-ui">已应用</span>和<span class="hfl-ui">未应用／已降级</span>。
4. 结合任务结果和主机实际可用磁盘空间，确认配置是否合适。

缓存状态反映最近确认的受管仓库连接，不表示所有历史缓存已同时调整或清空。应用失败时，会保留原有连接配置并上报状态；不要通过反复重装或重新注册主机来处理缓存配置问题。

## 容量规划建议

- **从默认预算评估**：磁盘空间允许时，可以从 `8192 MB` 开始，结合后续任务耗时、仓库访问情况和磁盘占用决定是否调整。更大的预算不保证每个任务都会更快。
- **按连接数量规划**：例如，同一主机有三个独立仓库连接，每个设置 `8192 MB`，仅内容和元数据缓存的合计预算就达到 `24576 MB`，而不是三者合用 `8192 MB`。
- **额外预留空间**：索引等其他缓存、日志、临时文件和恢复输出仍可能占用磁盘。配置值不是整个缓存目录或 Agent 安装目录的磁盘硬上限，不要把所在磁盘的全部剩余空间都分给缓存。
- **空间受限时谨慎调小**：降低预算或设为 `0` 可能增加远端读取开销；调整后验证实际任务表现。调小预算也不表示已有缓存文件会立即释放空间。
- **不要按数据量机械套用比例**：根据实际连接数量、工作负载和磁盘余量规划，不必为所有备份数据预留固定百分比的缓存。

## 缓存目录与安全边界

当前布局将可重建的仓库缓存放在 Agent 安装根目录下的 `cache/repositories/`。仓库连接配置位于 `data/kopia/repositories/`，安装身份、凭据和任务数据库不属于可随意删除的缓存。

不要在任务运行时手动清理缓存，也不要通过删除整个 Agent 目录、仓库连接配置或迁移记录来释放空间。旧版本升级且缓存布局迁移尚未完成时，历史缓存目录还可能包含需要保留的配置，不能直接整目录删除。

任务失败、组件离线或升级异常时，先查看任务详情，再按[安装与节点](/zh/docs/troubleshooting/installation-nodes)或[备份、存储与恢复](/zh/docs/troubleshooting/protection)中的步骤排查。
