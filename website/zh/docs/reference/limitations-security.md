# 限制与安全建议

## 当前边界

- 控制平面仅支持 Ubuntu 20.04/22.04/24.04 amd64。
- 完整 Data Gateway 当前要求 Linux/Ubuntu amd64。
- 未绑定 Proxy 的直接 NAS 目标只对已确认的 Linux 源端开放。
- 跨 Proxy 仓库访问需要源端可达的 Repository Server 地址和端口。
- 当前版本不支持把目标位置中已有的 Kopia Repository 直接导入为新仓库。
- 只有包含可用物理目录的成功或部分成功快照才能恢复。
- 文件级备份不自动提供数据库或业务应用的一致性保证。
- AI 回答由模型生成，必须核对原始文件和引用。

## 凭据与密钥

- 对象存储凭据使用最小必要权限和专用访问身份。
- 不在命令历史、截图、GitHub Issue 或文档示例中公开令牌、Secret Key、`.env` 或客户地址。
- 定期轮换长期凭据，并验证轮换后的下一次备份和恢复。
- Data Gateway 和外部模型 API 的凭据应按组织安全策略管理。

## 网络与 TLS

默认打包证书用于建立安装和测试兼容性，不是生产环境唯一身份。生产部署应使用与实际域名匹配的证书，并在浏览器和节点上建立正确的信任链。

不要通过长期关闭 TLS 校验解决证书问题。节点、Proxy、Data Gateway 和对象存储只开放必要地址与端口。

## 数据与删除

备份仓库、快照记录、恢复后的文件、Copilot 会话和网关工作区是不同的数据副本。删除其中一个对象，不代表其他副本都会同步删除。

执行删除前应查看界面列出的影响范围。不要使用指向 `/`、`/opt`、用户主目录或未解析变量的递归删除命令。

## 恢复责任

备份任务成功不能替代恢复验证。组织应定义恢复点目标、恢复时间目标、验证频率和负责人，并保留恢复演练结果。
