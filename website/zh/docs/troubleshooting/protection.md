# 备份、存储与恢复排障

## 无法浏览源目录

- 确认 Agent 或 Proxy 在线。
- 确认路径存在，并且运行服务的账户有读取和遍历权限。
- NAS 源确认挂载状态、共享凭据和协议端口。
- SMB 非 ASCII 文件名异常时，检查 Linux Proxy 的 `nls_utf8` 和 `iocharset=utf8`。
- 不要把 Windows 路径格式用于 Linux 节点，反之亦然。

## 对象存储验证失败

按错误类型检查：

- **凭据被拒绝**：Access Key、Secret Key 或临时凭据已失效。
- **权限不足**：身份不能列出存储桶或读写目标前缀。
- **存储桶不存在**：名称、区域或账户错误。
- **配置无效**：端点、区域、URL 方式或 TLS 配置不匹配。
- **网络或超时**：DNS、路由、防火墙或代理无法访问端点。
- **TLS 失败**：证书链、服务名称或主机时间错误。

对象存储时间偏差过大也会导致签名失败。先同步系统时间，再重试验证。

## NAS 或本地磁盘验证失败

- 确认绑定的 Proxy 在线。
- 确认共享地址、协议、凭据和本地挂载目录。
- 检查目标目录写权限和剩余空间。
- 跨节点访问时，确认源端能够访问 Proxy 的 Repository Server 地址和端口。
- 不要选择已存在其他 Kopia Repository 或其他业务数据的目录。

## 备份失败或部分成功

打开任务详情查看具体失败目录。常见原因包括源文件被删除、权限变化、文件被锁定、目标仓库中断或 Agent 离线。

部分成功快照只包含已经完成的范围。修复问题后重新执行备份，并验证新快照，不要假定失败部分会自动补入旧快照。

## 快照无法恢复

- 快照必须为成功或部分成功状态。
- 快照必须包含可用物理目录。
- 所选恢复范围必须位于该快照的已备份路径中。
- 恢复目标节点必须在线，目标目录必须存在且可写。
- 同一备份源已有恢复任务运行时，等待结束后再提交。

恢复任务被停止后，目标目录可能有不完整文件。检查并清理测试目录，再根据冲突策略重新执行。
