# 安装与节点

先查看安装程序或控制台显示的错误信息，再检查对应的系统与网络条件。

## Community 安装失败

依次检查：

- 是否为 Ubuntu 20.04、22.04 或 24.04 amd64。
- 是否通过 `sudo` 运行安装程序。
- Docker Engine 和 Compose V2 是否符合[系统要求](/zh/docs/deployment/requirements)，并且运行状态正常。
- 安装主机的 CPU、内存和 `/opt` 可用空间是否充足。
- `11442–11445/TCP` 是否已被其他程序占用。
- 主机能否连接安装源、镜像仓库和 Ubuntu 软件源。

安装程序提示存在不完整的旧安装时，不要直接覆盖安装目录。先保留完整提示并确认原环境是否需要恢复，再重新执行安装。

## 组件注册失败

- 从当前控制台重新生成安装命令，并在命令有效期内执行。
- 确认选择的操作系统与目标主机一致；Proxy 和 Private Data Gateway 使用受支持的 Ubuntu amd64 主机。
- Agent 应按需要保护的文件范围使用相应用户身份运行；Proxy 和 Private Data Gateway 按向导要求使用管理员权限运行。
- 确认目标主机能够解析并连接当前控制平面地址，且信任其 TLS 证书。
- 检查出口防火墙、安全组和网络代理是否允许所需连接。

## 组件安装后离线

1. 在控制台刷新组件状态，确认最后在线时间和当前版本。
2. 使用组件详情中提供的维护命令检查服务状态，必要时重新启动服务。
3. 检查组件到控制平面的 HTTPS/WSS 连接。
4. 确认组件版本与控制平面兼容。
5. 仍然离线时，再查看组件日志中的网络、证书或注册错误。

不要为了重新注册而直接删除节点数据目录。节点身份与控制台记录不一致时，应使用产品提供的移除、修复或重新部署流程。

## Private Data Gateway 安装失败

- 确认主机为 Ubuntu 20.04、22.04 或 24.04 amd64，并满足 CPU、内存和磁盘要求。
- 已安装 Docker 时，确认 Docker Engine 和 Compose V2 版本符合要求且运行正常。
- 主机未安装 Docker 时，确认安装程序可以使用当前 Release 提供的运行环境。
- 确认主机能够连接控制平面和需要访问的备份仓库。
- 根据安装程序显示的失败步骤检查下载、磁盘空间或 AI 引擎安装问题。

部署要求和步骤请查看[部署 Private Data Gateway](/zh/docs/deployment/data-gateway)。
