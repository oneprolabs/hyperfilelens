# 安装与节点排障

## 控制平面安装被拒绝

依次检查：

- 是否为 Ubuntu 20.04、22.04 或 24.04 amd64。
- 是否通过 `sudo` 运行安装程序。
- Docker Engine 和 Compose V2 是否满足要求且守护进程可访问。
- `/opt/hyperfilelens` 是否存在不完整安装，只包含 `.env` 或 `MANIFEST.json` 其中一个。
- 系统盘、镜像空间和内存是否充足。

安装程序为保护主机状态而停止时，不要绕过检查。先修复或清理明确的不完整状态，再重新运行。

## 节点注册失败

- 从当前控制台重新生成部署命令，避免使用过期注册信息。
- 确认目标主机时间准确。
- 确认 DNS 能解析控制平面地址，HTTPS 证书受信任。
- 检查代理、出口防火墙和安全组是否允许连接。
- 确认操作系统和架构与下载的安装包一致。

## 节点安装后离线

1. 检查节点服务是否正在运行。
2. 检查节点到控制平面的 HTTPS 和 WebSocket 路径。
3. 查看节点本地日志中的证书、身份或网络错误。
4. 检查控制平面显示的节点版本是否兼容。
5. 重启服务后观察是否自动重新连接。

不要为了重新注册而直接删除节点数据目录。节点身份与控制台记录不一致时，应使用产品提供的移除、修复或重新部署流程。

## Data Gateway 安装失败

- 完整安装必须使用 Linux/Ubuntu amd64。
- Docker 必须健康，Compose V2 可用。
- 已有 Docker 处于不完整或不兼容状态时，安装程序会停止。
- 检查 AI 引擎镜像或离线介质是否与当前控制平面版本一致。
- 检查网关工作区磁盘空间和到控制平面的网络。
