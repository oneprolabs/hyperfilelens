# 资源

资源目录汇总组织内受治理的业务对象及其归属信息。打开<span class="hfl-path">配置管理 → 组织管理 → 资源</span>，确认所有者、类型和授权关系是否与实际运维分工一致。

## 查看资源目录

资源列表通常包含：

- 资源名称与类型（例如备份源、仓库、网关等，以页面显示为准）；
- 所有者；
- 与组或其他授权范围相关的信息；
- 状态或最近更新时间。

可按名称、类型或所有者筛选，定位交接后仍挂在旧负责人名下的资源。

## 归属与授权

- **所有者**：对资源负有主要管理责任的账户。移交业务责任时应同步调整归属，避免出现“人已离职、资源仍挂在旧账号”的情况。
- **组授权**：通过[组](/zh/docs/governance/groups)把资源纳入协作范围后，组员可按组内角色访问；从组中移除资源后，组权限不再覆盖该资源。
- **组织级角色**：定义操作权限；每次组织角色分配单独选择自有资源或全组织资源，控制业务访问范围。组内角色可以独立增加针对本组资源的受支持操作；有效访问范围由适用授权合并确定，不是组织权限与组权限的交集。

## 修改所有者

修改所有者属于组织管理权限，不是普通业务资源操作。被明确授权的成员可以在本组织符合条件的成员之间交接符合条件的资源，即使其业务资源范围为自有资源。拥有资源或管理其所属组，都不能代替组织级交接权限。

单个与批量交接采用相同的授权规则。创建者历史、组关联、资源配置、数据和运行任务保持不变；接收所有权不自动增加角色权限。组织成员资格、资源有效性、版本冲突和审计要求均由后端强制检查。

## 日常检查

1. 新增备份源、目标存储或网关后，确认已出现在目录中且所有者正确。
2. 成员调岗或禁用前，检查其名下资源并完成移交。
3. 变更组资源范围后，用操作员账户验证可见性。

资源目录用于治理与授权，不替代数据保护页面中的连接验证和任务结果。删除资源或解除关联前，确认没有进行中的备份、恢复或洞察准备任务依赖该资源。

## 资源默认私有

成员的资源范围为 Own，且没有 Group 授权时，只能按已授予的操作权限访问当前归自己所有的业务资源，包括标签。标签名称在当前 Owner 内唯一，不要求整个组织唯一。Group 共享需要显式配置。恢复计划已有直接 Owner 时，不因父备份配置的所有权向其他成员开放；未分配直接 Owner 的计划保留明确的继承规则。

事件、告警、任务、恢复记录和投递历史跟随关联业务资源授权。拥有共享执行节点或通知渠道，不代表能查看其他成员的数据。个人 Chat 和请求历史仍按用户隔离。资源通知按当前权限检查，历史站内消息也不能绕过权限撤销。
