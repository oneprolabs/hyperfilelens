# 角色与权限

角色决定成员在组织内可以查看或执行哪些操作。打开<span class="hfl-path">配置管理 → 组织管理 → 角色</span>，查看默认角色、自定义角色，并在需要时恢复默认角色。

## 所有者与角色的区别

- **所有者**：组织身份，表示对该组织负有最高责任的账户关系；不会作为可删除的预设角色行出现在角色目录中。
- **角色**：可分配给成员的权限集合。新组织会自动提供一组产品预设角色，管理员可直接选用。

注册或创建组织时，系统不会把高级角色自动授予普通新用户；访问仍取决于成员关系与显式角色分配。

## 默认角色

企业版新组织默认提供以下角色：

| 角色 | 典型用途 |
| --- | --- |
| **管理员** | 在组织层面管理成员、数据保护、智能洞察和运维，可访问组织全部资源 |
| **管理者** | 管理组织治理；业务资源访问按归属与组授权确定 |
| **操作员** | 执行数据保护、使用智能洞察并查看运维信息；访问自有资源及组授权资源 |
| **审计员** | 只读查看组织治理及授权范围内的数据保护与运维信息，不修改配置 |

在[成员](/zh/docs/governance/members)中为用户选择与职责匹配的默认角色即可开始使用，无需先从零设计权限集。

上表描述的是角色自身授予的权限，不是对其它分配的限制。组内角色可以独立增加针对本组资源的受支持操作。因此，组织级审计员若被组内角色授予写权限，仍可修改对应组资源；请按[组](/zh/docs/governance/groups)中的说明同时检查两类分配。

## 自定义角色

若默认角色无法覆盖岗位职责：

1. 创建自定义角色并填写名称、说明。
2. 按需勾选权限（例如仅备份配置、仅告警查看等）。
3. 保存后，在成员管理中分配该角色。
4. 用目标账户验证关键页面可见性与操作是否符合预期。

授予管理类权限前应完成职责确认。能够管理成员或角色，不等于自动获得平台管理控制台权限。

## 恢复默认角色

如果预设角色被删除或需要重新创建缺失的默认角色：

1. 在角色页面选择<span class="hfl-ui">恢复默认角色</span>。
2. 先查看预览：将新建或恢复哪些角色。恢复已有预设时，会将其名称、说明、权限及启用状态重置为产品默认值，包括覆盖此前对该预设的编辑。
3. 确认后再执行恢复。

恢复默认角色不会把所有者改写成普通角色行。管理员已删除的预设角色，只有通过该恢复操作才会重新出现；组织初始化时不会自动恢复已删除的预设。

另行创建的自定义角色及成员分配关系不会更改，但已分配该预设的成员与组的有效权限会随角色定义变化。确认前应检查这些分配，尤其是此前曾收紧该预设权限的情况。

## 日常检查

- 默认角色齐全，或已通过恢复默认补齐。
- 成员所持角色与岗位匹配；需要资源隔离时配合[组](/zh/docs/governance/groups)授权。
- 侧栏和页面按有效权限显示。遇到“没有权限”时，先核对成员角色与组授权，再联系组织管理员调整。
