# 组

组用于在组织内划分协作边界：把成员和业务资源放到同一范围内，再通过组内角色控制可执行的操作。打开<span class="hfl-path">配置管理 → 治理 → 组</span>进行管理。

组织级角色授予组织权限；业务资源访问通常按归属确定，角色具备访问组织全部资源的权限时除外。组内角色可以独立授予针对本组资源的受支持操作。两类授权合并生效，组织级角色不是组权限的上限。

## 什么时候使用组

- 多个团队共用一个组织，但只能操作各自负责的备份源、仓库或网关。
- 需要给操作员开通部分资源权限，又不想授予组织管理员。
- 审计人员只需只读查看某一组资源的运行情况。

## 创建与维护组

1. 在组列表中创建组，填写名称和说明。
2. 添加组员，并从可用角色目录中选择角色；该角色中仅支持组上下文的权限会在本次组分配中生效。
3. 将需要纳入范围的资源加入该组，或按产品提供的范围选项配置可访问资源。
4. 保存后，用目标账户登录验证：应能看到授权资源，且看不到未授权资源。

组授权不会授予组织级治理权限。在组中分配的角色可以允许管理本组成员或资源，但不能通过该组分配获得组织角色管理、用量限额修改或平台管理能力。

例如，组织级角色为审计员的成员，仍可通过具备相应操作权限的组内角色获得本组资源的写权限。若需保持只读，应同时检查[成员](/zh/docs/governance/members)中的组织角色和所有组分配；组织级只读角色不会覆盖组授予的写权限。

## 日常检查

- 组说明与实际业务边界一致，避免“全能组”失去隔离意义。
- 离职或调岗后，及时调整组员与组内角色。
- 在[资源](/zh/docs/governance/resources)中确认所有者与组关联正确；资源从组中移除后，原组员不应再通过组权限访问。
- 删除组前，确认没有依赖该组授权才能完成的关键备份或恢复流程。
