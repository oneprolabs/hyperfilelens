# 完成首次备份

本流程以一台在线主机和一小段非关键测试目录为例。首次验证不要直接选择整块系统盘，先用可确认内容和大小的目录完成闭环。

## 1. 添加备份源

打开<span class="hfl-path">数据保护 → 源端资源</span>：

1. 选择添加源端主机，进入节点部署向导。
2. 选择目标操作系统，复制界面生成的当前注册命令。
3. 在目标主机上以要求的权限运行命令。
4. 返回控制台，等待节点显示在线并完成清单上报。

如保护 NAS，可添加 NAS 源并选择负责访问该共享的 Proxy。保存前确认共享路径、协议、凭据和字符集配置正确。

## 2. 准备目标存储

在目标存储页面选择一种仓库：

- **对象存储**：填写服务商、端点、区域、存储桶、对象前缀和凭据。
- **NAS**：填写共享地址与协议；可绑定 Proxy，也可在受支持条件下由源端直接访问。
- **本地磁盘**：选择 Proxy 及其上的专用目录。

目标路径应专用于 HyperFileLens。不要选择包含其他业务文件的现有目录，也不要在多个独立仓库间复用同一对象前缀。

## 3. 创建备份配置

打开<span class="hfl-path">数据保护 → 备份向导</span>并选择“创建备份配置”：

1. 选择刚添加的备份源。
2. 展开目录树，选择需要保护的文件或目录；也可以输入受支持的绝对路径。
3. 为每个源选择兼容的目标存储。
4. 选择备份策略、文件过滤规则和压缩选项；首次验证可以使用简单的手动执行方式。
5. 可选配置恢复计划。首次使用也可以先跳过，在产生快照后手动恢复。
6. 核对摘要并保存。

保存后，系统会在后台验证 Agent、挂载、写权限、Kopia 仓库及仓库归属。验证未通过前不要重复创建相同目标的配置。

## 4. 运行并验证

在备份向导的“开始备份”阶段选择已配置的源端并执行“立即备份”。等待任务结束，然后确认：

- 任务状态为成功；部分成功时应检查具体失败目录。
- 实际数据量与所选测试目录大致相符。
- 快照详情中可以看到预期目录和文件。
- 目标存储容量发生合理变化，没有写入错误位置。

最后从该快照恢复一个测试文件，验证内容、名称和时间是否符合预期。只有真正完成恢复验证，才能确认这条数据保护链路可用。

下一步：[查看任务与验证快照](/zh/docs/backup-restore/snapshots)或[恢复文件和目录](/zh/docs/backup-restore/restore)。
