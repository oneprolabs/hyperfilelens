# 源端主机损坏后恢复到新主机

当原始备份源主机永久损坏或离线时，你仍然可以从已有快照把数据恢复到替换主机。快照保存在目标存储仓库中，只要源端节点、仓库和快照未被删除，就可以用于恢复。

## 开始前检查

- 已损坏的原始主机不需要重新上线。
- 源端节点、仓库和历史快照在恢复验证完成前不能删除。
- 原始源端节点必须至少有一个可恢复的快照。**恢复** 按钮的可用性与节点在线或离线无关。
- 替换主机已准备好，操作系统已安装，磁盘空间充足。
- 替换主机已[安装 Agent](/zh/docs/deployment/agent) 并在控制台中显示为在线。
- 替换主机会获得新的节点身份，不会自动继承原始主机的备份配置。

## 恢复到新主机

### 1. 确认快照仍可用

1. 在控制台中打开 **保护 → 开始备份**。
2. 在源端列表中找到原始源端节点，其状态显示为 **离线**。
3. 确认该节点仍存在，且其历史备份和快照仍可查看。

![开始备份页面，显示离线的原始源端节点及其备份条目和快照点仍可见](/docs/zh/backup-restore/recover-new-host-verify-snapshots.png)

打开源端节点详情，确认历史快照时间点仍可用：

![快照详情抽屉，确认离线源端节点的历史快照点仍可用](/docs/zh/backup-restore/recover-new-host-verify-snapshots-detail.png)

在恢复完成并验证通过之前，不要删除离线的源端节点、仓库或快照。

### 2. 添加新主机并创建备份配置

1. 在替换主机上安装 HyperFileLens Agent。
2. 将 Agent 注册到同一控制台。替换主机会作为独立的 **在线** 节点出现，拥有不同的节点标识。
3. 将替换主机添加为备份源，并为它创建备份配置。参考[创建并运行备份](/zh/docs/backup-restore/create-backup)完成配置步骤——选择备份范围、分配目标仓库并保存配置。
4. **先不要运行备份。** 恢复目标列表只显示已有备份配置的主机。保存配置即可让替换主机出现在可选恢复目标中。

![开始备份页面，同时显示离线的原始节点和在线的替换节点](/docs/zh/backup-restore/recover-new-host-both-nodes.png)

### 3. 将快照恢复到新主机

离线源端节点存在可恢复快照时，**恢复** 按钮即可使用。替换主机因已有备份配置，现已出现在恢复目标列表中。

1. 在 **开始备份** 中，选择离线的原始源端节点，然后选择 **恢复**。
2. 选择 **创建新的恢复任务**。不要使用 **运行恢复计划**——计划中预设的目标可能是原始主机。
3. 在 **备份和快照** 中，选择备份和所需的快照时间点。
4. 在 **恢复目标** 中，选择替换主机作为目标节点。
5. 选择恢复范围——整个快照、单个目录或具体文件。
6. 在替换主机上选择目标目录。
7. 设置冲突策略：
   - **跳过**——首次验证时推荐使用，更安全。
   - **覆盖**——仅在明确了解目标目录内容时使用。
8. 在 **确认信息** 中核对快照、目标节点、恢复范围、目标路径和冲突策略，然后选择 **开始恢复**。

![创建恢复任务页面，快照源选择了离线节点，恢复目标选择了新的在线节点](/docs/zh/backup-restore/recover-new-host-create-restore.png)

### 4. 验证恢复结果

1. 恢复任务完成后，在 **开始备份** 中确认 **恢复任务** 为 **成功**。
2. 打开原始源端节点详情中的 **恢复记录**，核对记录状态、恢复数量和目标路径。
3. 在替换主机上检查目标目录中的恢复文件。打开样本文件，确认内容与预期一致。

![恢复记录显示从离线源端节点到替换主机的成功恢复](/docs/zh/backup-restore/recover-new-host-restore-records.png)

在确认所有必要文件已在替换主机上完整恢复之前，不要删除原始节点、仓库或快照。

### 5. 为替换主机运行首次备份

替换主机在步骤 2 中已创建了备份配置，但尚未运行过备份。恢复验证通过后：

1. 在 **开始备份** 中，选择替换主机并选择 **立即备份**。
2. 等待 **备份任务** 变为 **成功**。如需详细步骤，参考[创建并运行备份](/zh/docs/backup-restore/create-backup)。
3. 为替换主机配置合适的[备份策略与保留规则](/zh/docs/backup-restore/policies)。
4. 确定恢复目标后，可选择性为替换主机配置恢复计划。

## 清理原始节点（可选）

在恢复已通过验证且替换主机已开始自行产生快照后，如果不再需要离线原始节点，可以将其删除。删除前请确认你的数据保留要求。
