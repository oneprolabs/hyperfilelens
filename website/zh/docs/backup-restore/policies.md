# 策略与保留

备份策略决定何时运行以及保留多少恢复点；文件过滤器决定哪些内容不进入后续快照。先用手动备份验证完整链路，再为稳定的数据范围添加策略。

## 备份策略

在 **Protection → Backup Policies** 选择 **Create Backup Policy**。编辑器提供 **Quick Schedule** 和 **Advanced Schedule**，并在右侧显示规则预览。至少需要确认：

- 策略是否启用；
- 调度时区、开始时间、周期和间隔，或高级 Cron 表达式；
- 最新、每小时、每日和每月恢复点的保留数量或时间范围；
- 不可读目录、不可读文件和不支持文件系统项的处理方式。

![Create Backup Policy 中的快速调度、保留和错误处理预览，个人账户已经模糊处理](/docs/backup-restore/backup-policy-editor.png)

调度频率应根据恢复点目标和数据变化速度确定。高频调度不会自动解决源端长时间离线、仓库不可达或任务运行时间超过间隔的问题。

## 保留规则

保留周期必须同时考虑业务恢复要求和目标存储容量。缩短保留期会减少可选历史时间点；延长保留期会持续增加仓库容量和维护开销。

同一快照可能同时符合多个保留层级。保存前以右侧 **Rule Preview** 为准，并确认目标仓库有足够容量。修改保留规则前确认：

- 最短需要回溯到哪个时间点。
- 是否存在合规或审计保留要求。
- 最近是否完成过恢复验证。
- 目标仓库是否有足够增长空间。

## 文件过滤

在 **Protection → File Filters** 选择 **Create File Filter**。可以选择临时文件、开发构建缓存和系统垃圾等快速预设，也可以逐行添加自定义排除规则。规则区分大小写；不要用逗号或分号把多个规则写在同一行。

![Create File Filter 中的快速预设和自定义排除规则编辑器，个人账户已经模糊处理](/docs/backup-restore/file-filter-editor.png)

还应检查最大文件大小、缓存目录和 **Current Filesystem Only** 等高级选项。排除规则适合缓存、临时文件和可重新生成的数据。不要仅为了让首次任务更快而排除尚未确认的数据范围。

规则变更只影响后续快照，不会补充已有快照中从未备份的文件。变更后应浏览下一次快照进行确认。

## 应用到备份配置

创建策略或过滤器后，返回 **Backup Configuration → Backup Setup**，为源端选择对应的 **Backup Policy** 或 **File Filter**。只创建规则不会自动影响已有备份配置。保存变更后检查下一次任务的触发时间、跳过项和快照内容。
